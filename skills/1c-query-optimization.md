# Оптимизация запросов 1С

Всегда предлагай более быстрый вариант запроса. Ниже — критические анти-паттерны и приёмы.

## Критические анти-паттерны (исправлять всегда)

### 1. Запрос в цикле
Никогда не выполняй запрос внутри цикла по данным. Собери все нужные ключи и сделай ОДИН запрос с отбором `В (&Список)` или соединением с временной таблицей.

### 2. Обращение к составному типу через точку
Поле составного (ссылочного) типа, разыменованное через точку, порождает неявные соединения со ВСЕМИ возможными таблицами — резко замедляет запрос. Сужай тип через `ВЫРАЗИТЬ`:
```
// плохо: неявные соединения со всеми регистраторами
ВЫБРАТЬ Регистратор.Номер ИЗ РегистрНакопления.ОстаткиТоваров
// хорошо: одно соединение
ВЫБРАТЬ ВЫРАЗИТЬ(Регистратор КАК Документ.РеализацияТоваровУслуг).Номер
ИЗ РегистрНакопления.ОстаткиТоваров
ГДЕ Регистратор ССЫЛКА Документ.РеализацияТоваровУслуг
```

### 3. Подзапрос в списке выбора (N+1)
Коррелированный подзапрос в SELECT выполняется для каждой строки. Замени соединением с заранее сгруппированными данными:
```
// плохо: подзапрос на каждую строку
ВЫБРАТЬ Ном.Ссылка, (ВЫБРАТЬ СУММА(О.Количество) ИЗ ... ГДЕ ...) КАК Остаток ИЗ Справочник.Номенклатура КАК Ном
// хорошо: соединение с виртуальной таблицей остатков
ВЫБРАТЬ Ном.Ссылка КАК Номенклатура, ЕСТЬNULL(Ост.КоличествоОстаток, 0) КАК Остаток
ИЗ Справочник.Номенклатура КАК Ном
  ЛЕВОЕ СОЕДИНЕНИЕ РегистрНакопления.ТоварыНаСкладах.Остатки КАК Ост ПО Ном.Ссылка = Ост.Номенклатура
```

## Высокий приоритет

### 4. Фильтр виртуальной таблицы — в ПАРАМЕТРАХ, а не в ГДЕ
Условия отбора для виртуальных таблиц (Остатки/Обороты/СрезПоследних и т.п.) передавай параметрами самой виртуальной таблицы — тогда платформа считает только нужные данные. Отбор в `ГДЕ` применяется уже ПОСЛЕ расчёта по всей таблице:
```
// плохо: РегистрНакопления.ОстаткиТоваров.Остатки() КАК Ост ГДЕ Ост.Склад = &Склад
// хорошо: РегистрНакопления.ОстаткиТоваров.Остатки(, Склад = &Склад) КАК Ост
```

### 5. Всегда ограничивай выборку: ПЕРВЫЕ N
Если нужен топ/пример/проверка существования — ставь `ПЕРВЫЕ N` (в 1С нет LIMIT, это единственный способ). Не тяни всю таблицу.

### 6. ИЛИ в условиях ухудшает работу индексов
Заменяй `ИЛИ` на `В (список)` либо разбивай на `ОБЪЕДИНИТЬ ВСЕ`:
```
// плохо: ГДЕ Организация = &Орг1 ИЛИ Организация = &Орг2
// хорошо: ГДЕ Организация В (&Орг1, &Орг2)
```

### 7. ПРЕДСТАВЛЕНИЕ вместо .Наименование
Для показа имени ссылки используй `ПРЕДСТАВЛЕНИЕ(Ссылка)` — это не создаёт лишнего соединения, в отличие от `Ссылка.Наименование`.

### 8. ОБЪЕДИНИТЬ ВСЕ вместо ОБЪЕДИНИТЬ
`ОБЪЕДИНИТЬ` убирает дубли (дорогая сортировка). Если дубли невозможны или не мешают — используй `ОБЪЕДИНИТЬ ВСЕ`.

## Временные таблицы

Разбивай сложные запросы на шаги через временные таблицы (`ПОМЕСТИТЬ ВТ_...`), а не вкладывай подзапросы в соединения. Правила:
- Большие ВТ (>1000 строк), участвующие в соединениях или в `В (ВЫБРАТЬ …)`, индексируй: `ИНДЕКСИРОВАТЬ ПО <поле>`.
- Минимизируй объём и число полей в ВТ.
- Никогда не создавай/не удаляй ВТ в цикле.
- Предпочитай соединение подзапросу (подзапрос в SELECT = проблема N+1).

## Индексы (писать под существующие)

- Платформа автоматически индексирует `Ссылка`, поля-измерения регистров (в порядке объявления), реквизиты/измерения с признаком «Индексировать».
- Фильтруй и соединяй по индексированным полям. Соединение/отбор по неиндексированному полю → скан всей таблицы.
- В регистрах порядок измерений важен: самое избирательное измерение, по которому чаще идёт отбор, должно идти первым.
- `ПОДОБНО "%текст"` с ведущим `%` не использует индекс — избегай ведущего `%`, если поле индексируемое.

## Порядок работы
1. Уточни структуру объекта (get_structure/describe), если не уверен в именах полей.
2. Составь запрос, сразу закладывая приёмы выше (параметры ВТ, ВЫРАЗИТЬ, ПЕРВЫЕ N).
3. Если результат большой или запрос медленный — примени временные таблицы и проверь отборы по индексам.
